# R-261022-0005：Windows 也进 CI，双端并行出包

## 变更背景与原因

1. 之前只有 `.github/workflows/macos.yml`。理由是 Windows 侧本地已有完整工具链
   （Qt 6.8.0 MinGW + Inno Setup + 108MB 的 `vlc/` SDK），一个 `package.bat` 就能出安装包，
   再让 CI 重复做一遍看起来是浪费。
2. 但这样有两个实际问题：
   - **版本容易对不上**：macOS 由 CI 按 tag 出包，Windows 由本机手打，
     `APPVER` 在 `package.bat` 里是硬编码的，两边版本号会漂；
   - **换机器就没法出 Windows 包**：新克隆一份仓库，没有 Qt、没有 Inno Setup、
     没有 `vlc/`，Windows 产物直接断供。
3. 目标：**一次 push，两端并行编出 dmg 与 Setup.exe**，版本号都从 `CMakeLists.txt` 读。

## 关键障碍：CI 拿不到 Windows 的 LibVLC SDK

实测官方 `vlc-3.0.21-win64.zip`（77 MB）的顶层目录只有：

```
AUTHORS  COPYING  NEWS  README  THANKS  axvlc.dll  hrtfs  libvlc.dll
libvlccore.dll  locale  lua  msi  npvlc.dll  plugins  skins  vlc.exe
```

**没有 `sdk/`**——头文件与导入库不在发行包里；而仓库里的 `vlc/`（108MB）是刻意不入库的。

## 变更具体内容

1. **把「编译期依赖」纳入仓库**（运行时依赖仍走官方发行包）：
   - 头文件：复用已有的 `thirdparty/vlc/include/vlc/`（15 个头文件，LGPL-2.1+，macOS 构建已在用）；
   - 导入库：新增 `thirdparty/vlc/lib/win64/libvlc.lib`（253 KB）、`libvlccore.lib`（576 KB）。
     这两个是 MinGW 也能直接链接的导入库，合计约 830 KB，随仓库分发没有负担。
2. **CMake 新增「只有仓库内 SDK」的探测分支**（`thirdparty/vlc` 分支重写）：
   - 头文件取 `thirdparty/vlc/include`；
   - 导入库按平台依次找 `lib/win64` → `lib/macos` → `lib`，
     认 `libvlc.lib` / `libvlc.dll.a` / `libvlc.dylib` 三者之一；
   - 运行时 bin 目录优先用根目录 `vlc/`（CI 从官方包解出来的 dll + plugins），
     拿不到再回退 `thirdparty/vlc/bin`。
   - 本地原有 `vlc/sdk/include` 分支排在前面，**开发机行为完全不变**。
3. **新增 `.github/workflows/windows.yml`**：
   - `windows-2022` runner，`jurplel/install-qt-action@v4`（`win64_mingw` + `tools_mingw1310`）；
   - `curl` 下载官方 `vlc-3.0.21-win64.zip` → `7z` 解压 → 改名 `vlc`；
   - 组装 `vlc/sdk/include`（拷仓库头文件）与 `vlc/sdk/lib`（拷仓库导入库），
     让 CMake 走原来的 Windows 分支逻辑，**不需要在 CI 里写特判**；
   - Ninja 编译 → `dist/LiteVlcPlayer` 组装（windeployqt + libvlc.dll + plugins）
     → Inno Setup（镜像里没有就 `choco install innosetup`）→ 上传
     `LiteVlcPlayer-<ver>-Setup.exe` 与 `LiteVlcPlayer-<ver>-win64.zip`。
4. **触发条件与 macOS 对齐**：同一组 `paths`（`src/**`、`resources/**`、`packaging/**`、
   `thirdparty/**`、`installer.iss`、`CMakeLists.txt`、自身）+ `workflow_dispatch`，
   一次 push 两个工作流并行跑，互不阻塞。

## 本地预演（推 CI 前先跑通）

在 `E:/tmp/ciwin` 复制源码、删掉 `vlc/sdk`、只放官方包解出的 `libvlc.dll`/`libvlccore.dll`/`plugins/`，
完整复现 CI 链路：

| 阶段 | 结果 |
|---|---|
| CMake 配置 | `Found LibVLC Include: thirdparty/vlc/include`、`Lib Dir: thirdparty/vlc/lib/win64`、`Bin Dir: vlc` |
| 编译 | 26/26 步全绿，链接无警告 |
| windeployqt + 组装 | 331 个文件，136 MB |
| Inno Setup | `Successful compile (26.5 sec)`，产出 `LiteVlcPlayer-1.1.3-Setup.exe` 34 MB |

## 踩坑记录

- **Git Bash 下 `ISCC.exe /DMyAppVersion=1.1.3` 会被路径转换**，报
  `You may not specify more than one script filename`。本地调试要用
  `MSYS2_ARG_CONV_EXCL="*"` 或写成 `//DMyAppVersion=...`；
  CI 用的是 pwsh，不存在这个问题。
- 官方 win64 zip 是 `vlc-3.0.21/` 单层目录，解压后要 `Move-Item` 成 `vlc/`，
  否则 CMake 的根目录探测找不到。
- `installer.iss` 的 `Source` 依赖 `dist\LiteVlcPlayer\*`，所以**必须先组装 dist 再打 Setup**，
  顺序不能颠倒。
