# R-261022-0003：更新源改为 GitHub Releases，移除内置自建服务器地址

## 变更背景与原因

原设计把更新服务器（`host:port`）混淆后内置在 `UpdateService` 里，代价是：

1. **容易泄漏**：混淆只防肉眼，文档、提交历史、日志里一旦出现明文就等于失效。
   本次核查发现 `docs/R-261021-0004.md` 的早期提交里确实写了明文地址（已在本次一并清除，
   并重写历史）。
2. **维护成本**：自建更新服务器需要自己提供版本清单（manifest）与安装包托管，
   而项目本身已经要发 Windows 安装包与 macOS dmg，天然适合直接挂在 Release 上。
3. **分发一致性**：GitHub Releases 天然区分 tag 与附件，`releases/latest` 就是
   "最新稳定版"，不需要自造一套清单格式。

## 变更具体内容

1. **`UpdateService`** 删除 `releaseEndpoint()` / `manifestUrl()` 与 XOR+Base64 三段乱序
   的全部实现（地址、密钥、片段一并移除，源码里不再有任何服务器地址）；
   改为：
   - `repository()`：编译期注入的仓库 slug（`owner/repo`），未配置返回空串；
   - `latestReleaseApiUrl()`：`https://api.github.com/repos/<repo>/releases/latest`；
   - `releasePageUrl()`：`https://github.com/<repo>/releases/latest`（API 不可达时的兜底）；
   - `platformTag()`：按平台返回 `win-x64` / `macos-arm64`（用于匹配 Release 附件）。
2. **CMake**：新增缓存变量 `APP_UPDATE_REPO`，以宏注入；本次定为 `yc7en/LiteVLC`
   （换仓库时改这一处，或用 `-DAPP_UPDATE_REPO=owner/repo` 覆盖；留空则视为未配置）；
   `player.pro` 同步定义同一个值，保证 qmake 构建行为一致。
3. **主窗口「检查更新」**：仍为预留（`kUpdateEnabled == false`，不联网），
   提示文案改为说明更新源是 GitHub Releases，未配置仓库时明确提示「尚未配置 owner/repo」。
4. **文档**：`docs/R-261021-0004.md` 中残留的明文地址改为「GitHub Releases + APP_UPDATE_REPO」；
   重写 git 历史，把早期提交里的明文替换掉（仓库尚无远端，重写无副作用）。

## 为什么不是"私有仓库也能用"

GitHub 的匿名 API 只能读公开仓库。私有仓库必须把 token 内置到客户端，
反编译即可提取，等于没有保护。可选方案：

- 仓库设为公开（推荐，构建分钟数也更省）；
- 或单独建一个**只放 Release 附件**的公开仓库，源码仍私有，`APP_UPDATE_REPO` 指向它。

## 后续接入（本次不做）

`kUpdateEnabled = true` 后，在 `onCheckUpdate()` 里请求 `latestReleaseApiUrl()`：
解析 `tag_name`（去掉前缀 `v`）与 `currentVersion()` 做数值比较，若更新则列出
`assets` 中与 `platformTag()` 匹配的附件（`*-Setup.exe` / `*-arm64.dmg`），
点击后打开 `browser_download_url`。注意 API 匿名限流 60 次/小时（按 IP），
手动检查足够；国内访问 api.github.com 可能不稳，兜底用 `releasePageUrl()`。
