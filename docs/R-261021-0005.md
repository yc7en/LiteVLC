# R-261021-0005：HLS 插播广告过滤（本地中继）

## 一、变更背景与原因

用户播放 `https://vip.dytt-cinema.com/20251029/38877_d5c11ef9/index.m3u8` 时，播到 4 分 55 秒左右跳出广告，询问能否避免。

实测分析（清单 1857 分片 / 286 个 `#EXT-X-DISCONTINUITY` 块）：

- 正片块时长分布稳定：**全部 >= 16.7 秒**（中位数约 20 秒，5 片/块）；
- 该片混入 **8 个超短块**（4.9 ~ 14.2 秒），298.3s / 306.8s 两个块正好对应用户看到的 4:55 广告；
- 部分广告块的分片时长签名完全相同（6.667 / 2.133 / 3.233 / 3.733 秒）——同一批广告反复插入；
- 广告分片码率明显高于正片（~2.7 Mbps vs ~1.2 Mbps）；
- 广告与正片同 CDN 同目录，域名/路径过滤无效。

结论：广告以「DISCONTINUITY 短块」混在清单里，可以在本地改写清单剔除——即此前规划的阶梯第 ③ 步「本地中继」（`ResolvedStream.needRelay` 预留位）。

## 二、变更具体内容

### 1. `src/core/HlsFilter.h/.cpp`（纯逻辑，可独立单测）
- 识别主清单（`#EXT-X-STREAM-INF`）与媒体清单（`#EXTINF`）；
- 媒体清单按 DISCONTINUITY 分块，判据（保守，宁漏勿误删）：
  - 块数 < 5 不启用（普通无广告清单只有 0~2 个 DISCONTINUITY）；
  - 块时长中位数 M，`块时长 < 0.65 * M` 判为广告块；
  - 剔除总量 > 25% 总时长则放弃过滤（判定不可信）；
- 剔除广告块后保留块间 DISCONTINUITY 边界、`#EXT-X-ENDLIST` 等尾部标签；
- 分片 URI 一律改写为绝对地址（分片不过中继，内核直连 CDN）；
- 主清单把子清单 URI 改写为继续走中继的本地地址（含 `URI="..."` 属性内嵌写法）。

### 2. `src/core/HlsRelay.h/.cpp`（本地 HTTP 中继）
- `QTcpServer` 只绑 `127.0.0.1` 随机端口；上游地址登记为随机 token（`/t/<token>`）；
- 收到请求时按条目保存的 UA / Referer 拉上游清单（跟随重定向，15s 超时），交 HlsFilter 处理后回给内核，结果按 token 缓存（seek 不重复拉）；
- 回环上游强制绕过系统代理（独立 NoProxy 的 QNAM）；真实站点仍走系统代理，与 CmsClient/StreamProbe 行为一致；
- 拉取失败的 token 标记 failed，`wrapUrl()` 对该地址退回直连，避免反复走死路；
- 过滤生效发 `adsRemoved(blocks, seconds)` 信号。

### 3. 接线
- `MainWindow::hlsRelayUrl()`：在线播放三处 `openUrl`（正常解析 / TLS 预检失败兜底 / 内核报错换头重试）统一经它包装；非 m3u8 或开关关闭时原样返回；
- 过滤生效 OSD 提示「已跳过 N 处插播广告（约 X 秒）」；
- `ConfigManager` 新增 `hlsAdFilterEnabled`（默认开），设置窗口「在线播放」分组加开关。

### 4. 边界与安全
- 直播流（无 ENDLIST 的 EVENT/LIVE）同样按块过滤，但判据仍要求块数 >= 5；识别不了的原样透传；
- 中继只回 m3u8 文本，不代理分片，几乎零带宽开销；
- token 随机 + 仅回环监听，外部进程无法枚举访问。

## 四、验证（E:/tmp/hlstest）

单测 `hlstest`（23 项断言，全部通过）：
- 真实清单：286 块识别正确；剔除 7 块 / 55.5 秒（保守阈值 0.65*M 下 4:55 处两块及全部已证实广告块均被剔除，14.2s 的边界块保留）；1842 = 1857 - 15 分片；输出全部绝对地址；4:55 广告分片哈希 `7cd3500d...` 不再出现；输出可再次解析（279 块）；
- 主清单子清单改写、普通清单不动结构、分片绝对化；
- 中继端到端（本地源 + 真实 dytt 源）：主清单改写 → 子清单过滤 → adsRemoved 触发；失败地址退回直连。
