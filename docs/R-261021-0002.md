# R-261021-0002 播放页嗅探与失败归因

## 一、变更背景与原因

**触发场景**：用户播放《凡人修仙传》第 01 集，地址为

```
https://c1.ddbblffcdn.com/video/fanrenxiuchuan/第01集/index.m3u8
```

弹窗提示「该地址返回的是网页，不是视频直链（多半需要网页解析/嗅探）」。该提示由 `StreamProbe::evaluate()` 产出——一旦判定响应是 HTML 就直接 `finishFailure`，管线终止，用户除了换线路没有任何可行动空间。

**结构性观察**（基于量子源详情接口实测 301 条播放地址）：

| 地址形态 | 示例 | 占比 |
|---|---|---|
| 直链（日期 + 哈希目录） | `v.lzfile26.com/20250907/28965_ba77bad4/index.m3u8` | 301/301 = 100% |
| 虚拟路径（拼音目录 + 中文集数目录） | `c1.ddbblffcdn.com/video/fanrenxiuchuan/第01集/index.m3u8` | 本次故障样本 |

即：主流 CMS 源几乎全部直链，**嗅探属于长尾需求**；但一旦命中就是死路（该源整条线路不可用），因此需要补，但应控制在轻量实现内，不引入 WebView。

**根本问题有两层**：

1. **归因不足**：`StreamProbe` 把「HTML」当成一种错误，实际上它至少包含五种情况，对策完全不同（见下表）。当前提示等于什么也没说。
2. **无降级路径**：真播放页（HTML 内嵌 m3u8 / iframe）本可以被解析出来，却没有这一层。

| 类型 | 特征 | 嗅探是否有效 | 正确对策 |
|---|---|---|---|
| A 回源错误页 | 502/403/404 的 nginx / Cloudflare 页，体积小 | 无效 | 重试 / 换线路 |
| B 签名或时效缺失 | 302 回首页，或 HTML 提示 `auth_key` / `sign` | 无效 | 重新取地址 / 抓 token |
| C 真播放页 | HTML 内嵌 m3u8 或 iframe | 有效 | 内联嗅探 |
| D JS 计算页 | `eval(`、`\x..`、`atob(`、`document.write` | 需执行 JS | 归因为 D，提示不支持 |
| E 编码不匹配 | 路径含非 ASCII，服务端按 GBK 解码 | 无效 | 编码变体重试 |

## 二、目标与非目标

**目标**

1. 失败可归因：错误提示中带上状态码、Content-Type、`<title>`、体积、是否含 iframe / `eval(`，并能一键另存响应体供排查。
2. 播放页可解析：HTML → 候选播放地址 → 逐个复检 → 播放；最多两跳（页面 + 一层 iframe）。
3. **不新增依赖、不增加安装包体积**，纯 Qt + 现有 `StreamProbe`。

**非目标**（拆为后续条目）
- JS 执行 / 浏览器嗅探（见第八节演进路线；**若将来要做，用 WebView2 而不是 Qt WebEngine**）。
- 解析接口（`?url={url}` 型 API）。
- 本地 `127.0.0.1` 中继（分片级 header 与 Cookie）。若出现「主清单能过、分片 403」，必须补中继才能根治。

## 三、变更具体内容（设计）

### 3.1 管线改造

现状：

```
SourceDialog → OnlinePlayRequest → MainWindow::playOnlineEpisode → StreamProbe → VlcPlayer::openUrl
```

改为：

```
StreamProbe(首探) ─┬─ kind=Media ─────────────────────────────→ VlcPlayer::openUrl
                   ├─ kind=NeedsSniff → PageSniffer(候选) → StreamProbe(复检) → VlcPlayer::openUrl
                   └─ 其余 kind → 归因提示（含诊断信息）
```

`StreamProbeResult` 增加 `kind` 枚举（`Media` / `NeedsSniff` / `HtmlUnknown` / `HttpError` / `Timeout` / `Empty` / `InvalidUrl`），`ok` 语义保持不变；`NeedsSniff` 时 `ok=false` 但同时携带 body 与诊断字段，供 `PageSniffer` 消费。

### 3.2 `PageSniffer` 提取规则（按命中率排序）

| 顺序 | 规则 | 说明 |
|---|---|---|
| 1 | body 以 `#EXTM3U` 开头 | 服务端把清单以 `text/html` 吐出，直接当 m3u8 用 |
| 2 | `https?://[^\s"'<>\\]+\.(m3u8\|mp4\|flv\|mkv\|ts)(\?…)?` | 正文/脚本里的字面量 |
| 3 | JSON / JS 转义形态 | 先把 `\/` 还原成 `/` 再跑规则 2 |
| 4 | 常见键 | `"url"` / `"playUrl"` / `"videoUrl"` / `"source"` / `"file"` / `"src"` 后的字符串 |
| 5 | HTML 属性 | `<video src>`、`<source src>`、`data-src`、`data-url`、`<iframe src>` |
| 6 | 苹果 CMS 前端变量 | `player_aaaa = {"url": ...}` 取其 `url` |
| 7 | base64 | 长度 > 40 且字符集合法 → 解码后再跑 1–6 |
| 8 | 相对路径 | 按 `<base href>` → 当前 URL 所在目录解析 |

**约束**：候选去重、上限 20 条；只接受 `http(s)`；同域候选优先；iframe 递归最多 2 层、总子请求数 ≤ 4；总预算 15s。

### 3.3 复检与排序

- 排序：同域 > 含 `.m3u8` 后缀 > 其他；逐个交 `StreamProbe` 复检（单组超时 3s，只试前两组 header 组合）。
- 首个通过即用，并把该次实测的 UA/Referer 一并交给 LibVLC。
- 全部失败时，返回信息量最大的那条错误（**403/404 优先于超时**，因为可行动性更高）。

### 3.4 归因信息载体

`StreamProbeResult` 新增字段：`statusCode`、`contentType`、`bodySize`、`title`、`hasIframe`、`hasEval`、`bodyPreview`（前 512 字节）、`kind`。

UI 侧（`MainWindow::onStreamProbeFinished` 失败分支）：

- 弹窗分两段——第一段一句话结论（A/B/C/D/E 归类），第二段缩进展示诊断字段。
- 增加「另存响应内容」按钮，写到 `%TEMP%/lvsniff-<时间戳>.html`（>1MB 截断），便于用户回传真实页面。

### 3.5 编码变体试探（默认关闭，可配置开关）

对路径含非 ASCII 字符的地址，首轮全部失败后额外试 2–3 个变体：`第01集` → `第1集` → `01`；以及 GBK 百分号编码形态。**上限 3 次请求**，命中即用。此条为经验性猜测，需实测验证收益，故默认关闭。

## 七、演进路线与降级顺序（已确认的策略）

### 7.1 阶梯

```
① 直连（现状）
   └─ 失败且 kind=NeedsSniff
② 内联嗅探（本条目，~700 行）
   └─ 命中 m3u8 但分片 403 / 需要 Cookie
③ 本地中继 127.0.0.1（~400 行）
   └─ 地址根本不是静态文件，由 JS 在运行时拼出来（D 类）
④ 浏览器嗅探（WebView2，~600 行 + 打包改造）
```

**顺序不能颠倒**：② 解决「地址在页面里但没被直接给出」，③ 解决「地址对、但请求头/Cookie 不对」，④ 解决「地址在运行时才算得出来」。③ 的命中概率显著高于 ④，且不增加安装包体积、不引入浏览器进程；先上 ④ 会让中继问题被掩盖成「WebView 也没用」。

### 7.2 为退路预留的接口（本条目实施时必须做，否则后接 WebView2 要重构）

1. `StreamProbeResult::kind` 保留 `NeedsBrowser` 终态，而不是把所有 HTML 都归成 `HtmlUnknown`。这样 ④ 上线时只需处理这一种 kind。
2. 抽出 `StreamResolver`，统一输出契约：

```cpp
struct ResolvedStream {
    QString url;
    QString userAgent;
    QString referer;
    QByteArray cookie;        // 仅 ③④ 能填，② 永远为空
    bool needRelay = false;   // 分片需中继
    bool needCookie = false;  // 缺 Cookie 播不了
};
```

3. `MainWindow` 只依赖 `StreamResolver` 的结果，不出现「嗅探/浏览器」的分支判断。④ 上线时只往解析链尾部加一环，不动 UI。
4. 失败提示里保留 `kind` 与诊断字段，使「A 解决不了」这件事可以被统计，而不是靠主观感觉。

### 7.3 何时判定「A 解决不了」

不是凭感觉，用样本量化：

- 取现有 16 个启用源，各搜 3 部常见剧，记录每条的 `kind` 分布；
- 判定线：剩余失败中 **`NeedsBrowser`（D 类）占比 ≥ 15%** 才值得上 ④；低于此值说明失败主要是 A/B/E 类，加浏览器也救不回来，应该去修中继或换源。
- 若「命中 m3u8 但 `needRelay`」占比高，则直接排 ③ 的优先级，跳过 ④。

### 7.4 浏览器方案的技术选型（若要走到 ④）

- **用 WebView2，不用 Qt WebEngine**。Qt WebEngine 安装后约 175–210MB（`Qt6WebEngineCore.dll` 单体占 135–160MB，加 `icudtl.dat` ~10MB、资源 pak ~20MB、locale ~20MB、Quick/Qml 依赖 ~15MB），且是编译期不可裁剪的单体 Chromium。
- WebView2 在目标机器上通常已存在（Win10 1803+ / Win11 内置；本机已装 155.0.4283.62），只需带 `WebView2Loader.dll`（约 120KB），增量 1–3MB；能力等价（`WebResourceRequested` ≈ `QWebEngineUrlRequestInterceptor`）。
- 代价：Windows 专属、需写 COM 胶水（`ICoreWebView2`）、runtime 版本由系统决定、Win7/8 不可用。做成 CMake 开关，默认关闭。
- 参考：Tauri 2 也不打包内核（复用系统 WebView2），但它没有公开的请求拦截 API，同样要靠 `with_webview()` + `webview2_com` + `AddWebResourceRequested`，代码量与 Qt 侧写 WebView2 持平。即「换框架省体积，不省这层工作量」。
