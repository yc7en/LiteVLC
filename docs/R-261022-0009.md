# R-261022-0009：支持 Intel Mac（x86_64 构建）

## 变更背景与原因

1. R-261022-0002 上的 macOS 支持只出 arm64（`CMakeLists.txt` 默认 + `macos.yml` 单 job），
   Intel Mac 用户无法使用。
2. 2026-10 核实的环境事实：
   - GitHub `macos-13`（最后的免费 Intel runner）已于 2025-12 退役；
     替代标签 **`macos-15-intel` 可用至 2027-08**，之后 GitHub 不再托管 x86_64 macOS runner；
   - Qt 6.8 的 `clang_64` 官方包是 **universal（x86_64 + arm64）**，Intel 构建无需更换 Qt 包；
   - VLC 3.0.21 官方提供 `vlc-3.0.21-intel64.dmg`，与现有 arm64 下载逻辑只差文件名。
3. 路线取舍：采用「原生 Intel runner + 双 dmg」（约 1~1.5 天）；
   **不采用**交叉编译（macdeployqt 跨架构有已知坑，bundle 需人工修）与
   universal2 lipo 合并（1.5~2 天且每次 Qt/VLC 升级都要重验合并脚本，dmg 体积翻倍）。

## 变更具体内容

1. **macOS CI 矩阵化**（`.github/workflows/macos.yml`）：
   - `strategy.matrix` 两项：`arm64 → macos-15`、`x86_64 → macos-15-intel`，`fail-fast: false`；
   - VLC dmg 名、`CMAKE_OSX_ARCHITECTURES`、dmg 命名、artifact 名全部由矩阵变量驱动；
   - job 超时 40 → 50 分钟（Intel runner 是老硬件，首轮跑完可回看实际耗时）。
2. **`packaging/macos/bundle.sh`**：
   - 新增第 4 参数 `arch`（`arm64` 默认 / `x86_64` / `x64`，`x64` 自检时归一为 `x86_64`）；
   - 架构自检由硬编码 arm64 改为按目标架构过滤（原来塞入任何非 arm64 二进制直接 exit 2）；
   - dmg 名改为 `LiteVlcPlayer-<版本>-macos-<arch>.dmg`，**包含完整平台标签**。
3. **`UpdateService::platformTag()`**：macOS 按编译架构返回 `macos-arm64` / `macos-x64`
   （`Q_PROCESSOR_X86_64` 编译期判断）。dmg 资产名与 platformTag 保持一致，
   更新功能接入（`kUpdateEnabled`）时可按 platformTag 子串匹配 Release 资产。
   - 遗留：Windows 产物名（`-Setup.exe` / `-win64.zip`）与 `win-x64` 标签不一致，
     留待更新功能接入时统一。
4. **`CMakeLists.txt`**：仅更新注释，说明默认仍 arm64、x86_64 由 CI 显式传参。
5. 应用代码无架构相关改动：NSWindow 置顶、VideoToolbox 硬解、字体、数据目录
   均为 OS API，与 CPU 架构无关。
