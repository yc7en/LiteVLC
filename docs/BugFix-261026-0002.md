# BugFix-261026-0002 配置地址导入失败：站点按 UA 分流，浏览器 UA 拿到的是网页

## 一、缺陷描述

用户反馈形如 `http://124.71.19.220/c/1` 的配置地址导入失败，只看到一句 JSON 解析错误
（`JSON 解析失败：illegal value ... 偏移 0`），完全看不出问题在哪。

实测该地址：

```
curl -A "Mozilla/5.0 ... Chrome/124.0.0.0 Safari/537.36"  http://124.71.19.220/c/1
→ 302 Found，location: /
→ 跟随跳转后 200 text/html，32927 B，内容是「影视仓配置分发」的站点首页
```

换成客户端 UA：

```
curl -A "okhttp/3.12.1"   http://124.71.19.220/c/1
→ 200 application/json，20279 B，就是真正的配置
```

`okhttp/3.12.1`、`TVBox/2.0`、Android `Dalvik` 三种 UA 都能拿到 JSON；只要 UA 是桌面浏览器，
一律 302 回首页。**这是站点侧的 UA 分流（反爬 / 防直接访问），不是地址失效。**

根因在 `SourceDialog::startImportRequest()`：导入请求固定发送桌面 Chrome UA，
于是拿到的是首页 HTML，`QJsonDocument::fromJson` 在第一个字节 `<` 就失败，
报错信息又只有解析器的原始文本，用户无从判断。

## 二、修复方法与实现

`src/ui/SourceDialog.cpp`：

1. 导入请求的 UA 改成**客户端 UA**（`okhttp/3.12.1`）—— 配置分发站本来就是发给客户端用的，
   这才是「正确的身份」。
2. `startImportRequest()` 增加 `attempt` 参数：若响应体去空白后以 `<` 开头（判定为网页），
   自动换浏览器 UA 重试一次，兼容个别只认浏览器的站点。
3. 两次都只拿到网页时，弹窗改成可诊断的说明：最终地址（`reply->url()`，能看到被重定向到哪）、
   以及三条常见原因（复制的是首页/分享页、地址失效需登录、站点只对特定客户端下发）。
4. 顺手补了 `m_ignoreResults` 判断，避免关窗后回调还在弹框。

## 三、验证

新增 `E:/tmp/livetest/cfgimport.cpp`：用 Qt 分别以两种 UA 拉同一个真实地址，再喂给
`SourceManager::importConfig()`。

```
=== 浏览器 UA（修复前的行为） ===
  HTTP 200 | 最终地址 http://124.71.19.220/     ← 被 302 回首页
  体积 32927 B | 开头: <!DOCTYPE html>
  → 不是配置内容，按 UI 逻辑会提示「返回的是网页」

=== 客户端 UA（修复后的默认） ===
  HTTP 200 | 最终地址 http://124.71.19.220/c/1
  体积 20279 B | 开头: {"spider":...
  导入结果: 点播源 2 / 直播源 3 / 跳过点播 36 / 跳过直播 0
```

导入成功的内容（可作为解析链的回归样本）：

| 类型 | 条目 |
| --- | --- |
| 点播 | 🍀┃非凡┃资源（type 1）、🍀┃如意┃资源（type 1） |
| 直播 | 平台直播（zb.php）、Guovin（m3u8）、港澳台（nzk） |

## 四、遗留：这类配置的主体是 type=3，本客户端不支持

该配置 `sites` 共 38 条，其中 **36 条是 `type=3`**（`csp_Douban`、`csp_Config`、`csp_PanWebShare`
这类 drpy / js 爬虫，还依赖顶层 `spider` 的 jar）。本客户端只对接苹果 CMS 的 type 0/1，
所以导入后只有 2 个点播源可用，界面会如实提示「跳过 36 个 Spider 脚本源」。

要吃到这 36 个站，必须内嵌 JS 引擎（QuickJS/Duktape）实现 `csp_*` 爬虫协议 + 支持 jar 运行时，
属于独立的大特性，不在本修复范围内。**对用户来说：能用的是 2 个点播 + 3 个直播，不是 38 个点播。**
