# R-261021-0001 在线片源：自定义源 / 搜索 / 在线播放

## 一、变更背景与原因

原播放器是纯本地播放器：所有入口都通向 `QFileDialog`，`VlcPlayer` 只有 `openMedia(文件路径)` 一个加载方式，没有任何"片源"概念。

需求方明确收敛过一次范围：**不要重构整个播放器，只要能像 TVBox 那样自定义源、搜到片子、点开能播**。据此放弃了 Win-box 的三种脚本 Spider（jar / js / py，分别依赖 JVM / V8 / CPython）与网盘直链，只保留中文 TVBox 生态中占比最高的**苹果 CMS（MacCMS）type 0 / type 1 接口**，使实现控制在 2000 行量级。

选型结论（详见 `.workbuddy/memory/2026-10-21.md`）：

| 决策项 | 选择 | 放弃的方案及原因 |
|---|---|---|
| 片源协议 | 苹果 CMS `provide/vod` 接口（JSON + XML） | jar/py/js Spider：需外挂三个运行时，C++ 侧只能包 JNI，得不偿失 |
| 播放地址获取 | LibVLC 直连 + 注入 `:http-referrer` / `:http-user-agent` | 本地 127.0.0.1 中继（分片级 header、网盘直链才需要，留作后续） |
| 插件形态 | 编译进主程序的 `SourceDialog` | `QPluginLoader` 进程内插件：会锁死 ABI、且脚本死循环会冻住播放器 |

## 二、变更具体内容

### 2.1 源配置模型 `SourceManager`（单例，406 + 80 行）

- 解析 TVBox 订阅的**三种形态**：标准对象 `{"sites":[...]}`、裸数组 `[{...}]`、以及前述两种的 **Base64** 编码订阅。
- 站点字段兼容：`key` / `name` / `type` / `api` / `searchable` / `quickSearch` / `filter` / `ext` / `jar` / `spider` / `userAgent` / `referer`。
- 落盘位置：**程序所在目录**的 `sources.json`（与 `ConfigManager` 的配置同目录），首次运行若不存在则生成带注释说明的模板。
- `type` 不在 `{0, 1}` 范围的站点（jar/js/py/csp_ 等）**自动跳过并在导入结果里计数提示**，不会污染可用源列表。
- `effectiveUserAgent()` / `effectiveReferer()`：站点没填 UA/Referer 时给默认值，**Referer 缺省取 api 的 origin**——这一条能过掉相当一部分防盗链站点。
- 懒加载：`instance()` 内部用函数内 `static` 做一次 `load()`，解决"配置文件永远不生成"的初始化漏洞（该漏洞在 BugFix-261021-0001 联调时发现并已修正）。

### 2.2 苹果 CMS 接口客户端 `CmsClient`（566 + 135 行）

- 查询参数：`ac=videolist`（部分站只认 `ac=detail`，**失败时自动降级重试一次**）、`wd=` 搜索、`ids=` 详情、`t=` 分类、`pg=` 翻页。
- 响应解析：`format=json` 走 `QJsonDocument`；否则走 `QXmlStreamReader`，两条路径产出同一个 `VodDetail` 结构。
- **编码兜底**：先按 UTF-8 解码，出现替换字符时回退 `QStringConverter::System`（中文 Windows 即 CP936/GBK），老站点不乱码。
- 播放列表三级拆分：`$$$` 分线路 → `#` 分集 → `$` 分「集名 / 地址」，并兼容部分站点用 `#` 直接分集、无线路层的写法。
- 每个请求带 `QNetworkAccessManager` 超时定时器，回调统一用 `siteKey` 标识，支持多源并发。

### 2.3 片源对话框 `SourceDialog`（752 + 106 行）

两个页签：

- **在线搜索**：多源并发搜索、边到边显示（不等待全部返回）、结果表按源站分组；选中一行 → 右侧出详情（简介、线路下拉、剧集列表）；双击剧集发 `playRequested(OnlinePlayRequest)`。
- **源配置**：支持「订阅链接 / 本地文件 / 剪贴板」三种导入方式，表格内逐源勾选启停、显示类型与可用性，可删除、可导出。

健壮性：`reject()` 时 `abort()` 所有在途请求并置 `m_aborted`，避免结果回调打到已析构的窗口。

### 2.4 播放层改造 `VlcPlayer`

- 新增 `openUrl(url, userAgent, referer, hwAccel, hwBackend)`：走 `libvlc_media_new_location`，并通过 `libvlc_media_add_option(":http-referrer=...")` / `:http-user-agent=...` 注入请求头。
- 新增 `isStreaming()`：网络流不写本地进度记忆（直链带时效签名，存下来无意义），`MainWindow` 的进度存取路径据此分流。

### 2.5 主窗口接入 `MainWindow` / `ControlBar`

- 入口：菜单「媒体 → 在线片源」、快捷键 **Ctrl+F**、控制栏「在线」按钮。
- 整条线路自动连播：`OnlinePlayRequest` 保存 `episodes` 与 `startIndex`，一集播完自动 `playOnlineEpisode(index+1)`；手动上一集/下一集在在线队列存在时**优先走队列**，否则回落到本地播放列表。
- 与既有「自动跳过片头片尾」「记忆播放」共存：在线流跳过记忆，片头片尾逻辑照旧。

## 四、关键接口约定（后续扩展请沿用）

```cpp
// SourceManager
QList<SourceSite> sites(bool onlyEnabled = true) const;
QStringList importFromUrl(const QString &url, QString *error);   // 返回新增 key 列表
QStringList importFromFile(const QString &path, QString *error);

// CmsClient
void search(const SourceSite &site, const QString &keyword, int page);
void detail(const SourceSite &site, const QString &vodId);
// 回调均为信号：searchFinished(siteKey, items, error) / detailFinished(siteKey, detail, error)

// 播放请求（SourceDialog → MainWindow）
struct OnlinePlayRequest { QString title; QList<VodEpisode> episodes; int startIndex;
                           QString userAgent; QString referer; };

// VlcPlayer
bool openUrl(const QString &url, const QString &userAgent, const QString &referer,
             bool hwAccelEnabled, const QString &hwBackend);
```

## 五、已知边界

- 仅支持可直接 GET 的苹果 CMS type 0 / 1 接口；`jar` / `js` / `py` / `csp_` 类 Spider 导入时跳过。
- 无本地中继，分片级防盗链的 m3u8 与网盘直链尚不支持。
- 无网页解析 / 嗅探，返回 HTML 的线路会在预检阶段明确报错（见 BugFix-261021-0001）。
- 无发现页 / 分类浏览 / 弹幕。
