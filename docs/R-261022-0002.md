# R-261022-0002：macOS（Apple Silicon）编译支持

## 变更背景与原因

用户目标平台增加 macOS，但**没有 Mac 真机**。GitHub Actions 的 `macos-15` runner 是
真 Apple Silicon 硬件，可以作为唯一的编译/打包环境。因此本次做的是"编译前准备"：

- 让工程在 macOS 上能配置、能编译、能出 `.app` 与 dmg；
- 把平台差异收敛到少量分支，避免污染已经验证过的业务逻辑；
- 打包流程脚本化，CI 与本地 Mac 用同一套。

范围限定：**只做 arm64**（不做 universal），**不做公证**（无 Apple 开发者账号）。

## 变更具体内容

### 1. 构建系统（CMakeLists.txt）

- 新增 Apple 分支的 VLC 探测：`vlc/VLC.app/Contents/MacOS`、`thirdparty/VLC.app/...`、
  `/Applications/VLC.app/Contents/MacOS`，取其 `lib/` 与 `plugins/`；
- macOS 头文件改用仓库内 `thirdparty/vlc/include`（VLC.app 不带头文件，把这些
  LGPL 头文件纳入仓库后 CI 不必再拉源码包）；
- `CMAKE_OSX_ARCHITECTURES` 默认 `arm64`，`CMAKE_OSX_DEPLOYMENT_TARGET` 默认 `12.0`（Qt 6.8 要求）；
- `MACOSX_BUNDLE` + `MACOSX_BUNDLE_INFO_PLIST` 模板 + `app.icns` 进 Resources；
  `INSTALL_RPATH=@executable_path/lib;@executable_path/../Frameworks`；
- Windows 分支保持原样（dll 拷贝、`WIN32_EXECUTABLE`、`app.rc`）。

### 2. 平台分支（代码）

| 位置 | 处理 |
|---|---|
| `src/platform/MacWindow.{h,mm}`（新增） | macOS 用 `[NSWindow setLevel:]` 切置顶；其他平台内联空实现，调用方不写 `#if` |
| `MainWindow::onSetStayOnTop` | 增加 `Q_OS_MAC` 分支。**不能**用 `setWindowFlag`，会重建 NSWindow 使 LibVLC 绑定失效（黑屏） |
| `MainWindow::onToggleFullScreen` | macOS 菜单栏在系统顶栏，`QMenuBar::hide/show` 无效，跳过 |
| `AppPaths` | 新增 `insideAppBundle()`：`.app` 包内即使可写也不落配置（会破坏签名封印），统一走 `~/Library/Application Support/LiteVlcPlayer` |
| `VlcPlayer` 插件探测 | 删除硬编码的 `e:/02code/player/vlc/plugins`，新增 bundle 相对路径 `Contents/MacOS/plugins`、`../Frameworks/plugins` |
| `SettingsDialog` 硬解后端 | macOS 只列 `any` / `videotoolbox`；配置里残留的 `d3d11va` 等不在列表时回退到「自动」 |
| `resources/dark_modern.qss` | 字体链补 `PingFang SC`、`Helvetica Neue` |

### 3. 资源与打包

- `resources/app.icns`：由 `E:/tmp/icongen` 从 `app.svg` 生成（icp4/icp5/icp6/ic07/ic08/ic09/ic10，PNG 条目）；
  ico 顺带收紧为 ≤256，避免无谓体积；
- `packaging/macos/Info.plist.in`：版本号由 CMake 注入，含 `CFBundleDocumentTypes`
  （视频/字幕/播放列表）、`NSHighResolutionCapable`、`LSMinimumSystemVersion 12.0`；
- `packaging/macos/bundle.sh`：拷 `lib/` 与 `plugins/`（**保持 VLC.app 内部相对布局**）→
  `install_name_tool` 把所有 libvlc/libvlccore 引用改成 `@rpath/` → 补 `@executable_path/lib`
  rpath → **arm64 自检（混入 x86_64 即中止）** → 逐文件 ad-hoc 签名 → `hdiutil` 出 dmg
  （内含"右键打开"说明）。

### 4. CI（`.github/workflows/macos.yml`）

`macos-15`（arm64）+ Qt 6.8.0（install-qt-action）+ `vlc-3.0.21-arm64.dmg`（SHA-256 校验）
→ CMake → 编译 → `macdeployqt` → `bundle.sh` → 上传 dmg artifact。

### 5. 其它

- `.gitignore`：`vlc/` 改为 `/vlc/` 锚定根目录（否则会连带忽略 `thirdparty/vlc`），新增 `*.dmg`；
- `player.pro`：补 `macx` 块（头文件路径、`.mm`、icns），版本宏同步到 1.1.3。

## 影响面与风险

- Windows 构建已复测通过（CMake 配置 + 全量编译，无警告新增）。
- **未验证**：macOS 上的实际编译与运行（无 Mac、无 CI 环境）。首次 CI 运行预计需要
  2–4 轮修正，常见问题：Qt 包架构、`macdeployqt` 对 rpath 的处理、插件签名顺序。
- **核心风险不变**：LibVLC 3 嵌入 Qt6 的 layer-backed NSView 是否黑屏，CI 无法验证，
  需第一版 dmg 在有 Mac 的人手里点一次。
