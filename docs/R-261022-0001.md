# R-261022-0001：订阅导入失败提示带统计、混合配置导入告知跳过数

## 变更背景与原因

用户导入 `https://jijietvbox.lol/jieluntan-fty.json`（饭太硬系配置）时弹「导入失败：
配置里没有可用的接口源…」。经分析该配置 **50 个源全部是 type=3**（csp_*Guard 系列，
需要 TVBox 的 spider jar 运行时执行，其中 spider 字段就是伪装成 jpg 的 jar 下载地址），
确实没有任何 type=0/1 苹果 CMS 接口——解析行为正确，但旧提示没有数字、没有分类，
用户无法区分「配置问题」与「软件问题」。

两种场景需要区分：
1. **完全不可用**（如本例）：应讲清共多少源、各是什么类型、为什么不能用、该怎么办；
2. **混合配置**（同一份里有 CMS 也有 Spider 源）：导入成功时也要说明跳过了多少个
   Spider 源，否则用户会疑惑「明明配置里 20 个源怎么只导入了 3 个」。

## 变更具体内容

1. **`SourceManager.h`**：新增 `ParseStats` 结构（totalSites / spiderSkipped /
   otherSkipped / imported）；`parseSubscription` / `importSubscription` 增加可选
   `ParseStats *` 出参。
2. **`SourceManager.cpp`**：解析时按条目分类计数；结果为空时报错改为多行说明：
   共 N 个源 → Spider 源 X 个（说明 jar 运行时原因）→ 其他不支持 Y 个 → 建议
   换用 type=0/1 接口的订阅。
3. **`SourceDialog::importPayload`**：导入成功时若跳过数 > 0，提示「另有 N 个源
   未导入：X 个 Spider 脚本源（type=3，需 jar 运行时），Y 个其他不支持源」。

## 验证

测试台 `E:/tmp/smtest`（用真实 fty.json + 手造混合配置），7 项断言全部通过：
- fty.json：50 源全部识别为 type=3 Spider，报错带总数与原因；
- 混合配置（2 CMS + 1 Spider）：导入 2 个、spiderSkipped=1、imported=2。
