# R-261026-0001 桌面端支持 TVBox 直播源（lives）与统一导入

## 一、变更背景与原因

此前 `SourceManager` 只能消费 TVBox 配置里的 `sites`（type=0 XML / type=1 JSON 的苹果 CMS 接口），
`lives` 数组完全没接。实际用起来的感受是「导入了一份 TVBox 配置，点播有了、直播没了」，
还得另开一个软件看电视——这跟「兼容 TVBox 生态」的目标差了一半。

而直播这块的技术成本其实极低：

- 直播源就是一个 `m3u` / `txt` 清单，解析出来是 `m3u8` / `rtmp` / `rtsp` 地址；
- 现有 `StreamProbe` 对非 http(s) 协议是 **PassThrough 直通**，`StreamResolver` 不用改一行；
- 播放队列已经统一走 `PlaylistManager`，把整组频道塞进去就天然有了「下一集 = 换台」。

所以本轮只补「清单怎么来、怎么解析、怎么展示」三层，不碰播放内核。

## 二、变更具体内容

### 1. 新增 `LiveParser`（纯函数，无网络无 GUI）

- **三种形态自动识别**：`#EXTM3U` → m3u；含 `#genre#` → txt；有 `名称,地址` 行 → txt；否则按裸地址列表。
- m3u：取 `tvg-name` / `tvg-id` / `tvg-logo` / `group-title`，频道名取最后一个逗号之后；`#EXTGRP:` 覆盖当前分组。
- txt：`央视,#genre#` 之后每行 `频道名,地址`；`频道,url1#url2` 多线路只取第一条。
- 编码：UTF-8 优先，出现 U+FFFD 回退系统编码（中文 Windows 即 GBK）——老 txt 清单基本都是 GBK。
- 去重按「名称 + 地址」，分组列表保持首次出现顺序；空分组统一记「未分组」。

### 2. 新增 `LiveClient`（拉取）

- 一源一请求，默认 UA / Referer（Referer 取清单地址的 origin），`NoLessSafeRedirectPolicy`，20 秒超时。
- 本地文件（`file://` 或磁盘路径）直接读盘，不联网。
- `abortAll()` 清表后再 `abort()`，被中断的请求不会再发信号（关窗安全）。

### 3. `SourceManager` 扩展

- 新增 `LiveSource`（`isRemote` / `localPath` / `typeLabel` / `effectiveUserAgent` / `effectiveReferer`）
  与 `lives()` / `enabledLives()` / `mergeLives()` / `setLiveEnabled()` / `removeLive()` / `findLive()`。
- `sources.json` 增加 `lives` 数组：**旧文件天然兼容**（没有该字段就是空列表，不迁移不报错）。
- 新增 `parseLives()`：只收「有清单地址」的条目；只有 `api`（`csp_*` 脚本型）的计入 skipped。
- 新增 `importConfig()`：一次解析 `sites` + `lives`，返回 `ConfigImportResult`
  （各自导入数、跳过数、是否出现过对应字段、失败原因），界面据此给出「导入了什么、漏了什么」。
- 顺手把 base64 兜底抽成 `parseConfigJson()`，`sites` 与 `lives` 共用同一套解析入口。

### 4. `SourceDialog`

- 新增第三个页签「直播」：直播源下拉 + 刷新频道 + 分组下拉 + 频道名筛选；
  频道表（频道 / 分组 / 来源）；双击播放；「▶ 播放选中频道」与「＋ 加入播放列表」。
- **换台设计**：播放时把**当前筛选结果整组**塞进播放列表，起始下标指向选中频道，
  于是 PgUp / PgDn 就是换台，不需要额外的「频道上下键」逻辑。
- 每到一个源就重建一次表格（增量可见），分组下拉保住用户当前选择，筛选后尽量保住选中行。
- 源配置页拆成「点播源」与「直播源」两张表（各自启用勾选），共用一个「删除选中」按钮；
  新增「添加直播源」按钮（手填 m3u / txt 地址，key 用时间戳）。
- 导入提示改为逐项报告：导入 N 个点播源 / M 个直播源，并列出未导入的类型与数量。

### 5. `MainWindow`

- 新增菜单项「直播频道(&L)...」`Ctrl+Shift+L`：复用同一个片源窗口，切到直播页。

### 6. 直播绕开 HLS 中继（关键）

`HlsRelay` 对清单是**按 URL 永久缓存**（`entry.hasCached` 命中就直接吐旧清单），
这对点播没问题，但直播清单是滑动窗口，缓存后画面会停在旧片段上。

- `PlaylistEntry` 增加 `live` 标记（`makeOnline(..., isLive)`）；
- 直播条目播放时直接用解析出的原始地址，三处 `hlsRelayUrl()` 调用（正常播放 / TLS 兜底 / 换头重试）
  都按 `entry.live` 分支绕开。

### 7. 附带修复：Referer 丢端口

`SourceSite::effectiveReferer()` 原来用 `QUrl::host()` 拼 origin，自定义端口的源站会得到
`http://127.0.0.1/` 而不是 `http://127.0.0.1:18090/`，防盗链校验必然 403。改为 `authority()`。
这个坑对点播和直播都成立，是测试里被 mock 服务器（校验 Referer 前缀）打出来的。

## 三、验证

测试台 `E:/tmp/livetest`（不在仓库内）：

- `livetest`：**32 项断言全过** —— m3u（属性/分组/`#EXTGRP`/rtmp 保留）、txt（分组行/多线路取首条）、
  GBK 解码、裸地址列表、去重、`parseLives`（含脚本型跳过）、`importConfig` 统计、
  落盘→重载（`lives` 真的写进 `sources.json`）、停用后 `enabledLives` 减少、
  `LiveClient` 本地读盘 / 远程拉取（mock 服务器校验 UA 与 Referer）/ 404 报错。
- `livesmoke`：**12 项 UI 冒烟全过** —— 真实 `SourceDialog` 三页签、点「刷新频道」、
  频道进表（名称/分组/来源列）、分组下拉、播放时整组进列表 + 起始下标 + UA/Referer + `live` 标记。
- 主程序 `cmake --build build` 通过，启动 5 秒存活冒烟通过。
