# R-261022-0004：README 双语化（英文主入口 + 中文单列）

## 变更背景与原因

1. **仓库要推到 GitHub**：GitHub 会把仓库根目录的 `README.md` 直接渲染成项目首页，
   而原 `README.md` 全中文，非中文用户打开后读不到任何可用的信息。
2. **单文件双语是坏方案**：一份 README 里中英混排会让两种语言的读者都在找自己那段，
   而且首屏被拉长；分成两份文件、头部互链才是常见做法。
3. **需要保留中文全文**：现有中文 README 内容密度高（功能清单、快捷键、排障分类 A~E、
   构建步骤、变更记录），翻译不能让中文版缩水，因此中文内容整体平移，不做删减。

## 变更具体内容

1. **语言分工**
   - `README.md`：**英文**，作为仓库主入口（GitHub 首页默认渲染）；
   - `README.zh-CN.md`：原中文 README 全文，仅做「文件名迁移 + 头部加切换」；
   - 用 `git mv` 迁移，保留中文内容的历史追溯（`git log --follow` 可用）。
2. **头部切换**：两份文件第 1 行分别是
   - `README.md`：`**Eng** | [中文](README.zh-CN.md)`
   - `README.zh-CN.md`：`[Eng](README.md) | **中文**`
   当前语言加粗不可点，另一种语言给链接，避免用户点到"自己正在看的这份"。
3. **英文版内容对齐**：章节结构与中文版一一对应（功能清单 4 组 / 快捷键表 / 在线源配置与
   排障表 / 构建与运行含 macOS CI / 变更记录），术语统一为
   `always-on-top`、`hotlink protection`、`mid-roll ad`、`ad-hoc signing` 等固定译法；
   代码块、命令、路径、`sources.json` 字段名保持原样不译。
4. **变更记录**：两份 README 的第 5 节各加一行 `R-261022-0004`。

## 维护约定（重要）

- 之后任何改 README 的提交**必须同时改两份**：`README.md` 与 `README.zh-CN.md`。
  只改一份会造成中英内容分叉，比没有英文版更糟。
- 新增文档条目时，两份 README 的「变更记录」表格都要加行（编号相同，摘要各用对应语言）。
- 文件名用 `README.zh-CN.md`（语言标签带地区），便于将来再加 `README.ja.md` 之类。
