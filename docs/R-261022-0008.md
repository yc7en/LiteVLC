# R-261022-0008：自动字幕与自动翻译（ASR + MT）

## 变更背景与原因

1. 本地文件与在线片源大量无字幕或只有外挂字幕，外语片、生肉、录像切片基本没法看。
2. 参考项目 `github.com/dlsandy/Transub-Player`（WPF + mpv + whisper.cpp + llama-server）
   验证了「边取边识别、增量出字幕」的可行性；该项目**无 LICENSE**，
   只借鉴架构思路，代码全部自写。
3. 调研结论（2026-10）：
   - Whisper 在中文长音频上 CER 约 20%，SenseVoice-Small 约 7.8% 且 CPU 上快一个量级；
   - 输入法级精度的来源是「真实数据 + 用户纠错闭环 / 短句流式即时纠错 /
     用户词库热词注入 / 标点恢复 + ITN 后处理」，其中**热词注入**和**标点/ITN**
     可以在播放器里复刻（详见「同音词三层防御」）。
4. 全程本地离线：无 API key、无调用费用、音频不外传。

## 变更具体内容

### 总体流水线

音频获取（按源类型分流）→ 16kHz mono PCM 分块 → VAD 切分 →
ASR（sherpa-onnx 主 / whisper.cpp 兜底）→ LiveSubtitleStore（cue 模型 + 增量 SRT）→
SubtitleOverlay 自绘显示；MT（llama-server）作为独立消费者批处理翻译后回填。

### 1. 音频获取：按源类型分流（关键设计）

| 源类型 | 方式 | 说明 |
|---|---|---|
| 本地文件 | 播放前预转码整条为 WAV | 磁盘读取无成本，ASR 可超前播放，字幕先齐再开播 |
| 网络点播（HLS/DASH/渐进式） | 分块预取：播放头前方保持 5~10 分钟 | 独立 libvlc 实例（no-video + sout 转码 16kHz mono WAV，start-time/stop-time 控制分块）解封装源地址；地址取 `StreamResolver` 结果（含 Cookie/Referer），开启广告过滤时用 Relay 改写后的 m3u8，避免把广告也转成字幕 |
| 直播 / DRM / 拿不到直链 | 实时 dump 播放中音频（sout） | 唯一兜底；字幕必然落后 2~4 分钟（SenseVoice CPU 17× 实时，追得上），UI 明示 |

- 预取与播放**解耦**：预取用独立的第二个 libvlc 实例，不干扰播放实例；
  只有直播兜底模式才对播放中的音频做 sout dump。
- seek 时重置分块游标；cue 时间轴以音频文件偏移为准，与播放头对齐后写入。
- **不打包 ffmpeg**：libvlc 本身就是解封装器，AES-128 HLS 项目里已有处理经验
  （BugFix-261021-0002、R-261021-0005）；设置里可留「系统存在 ffmpeg 则优先」的
  可选项（非必须，默认不启用）。
- 网络较慢导致预取缓冲耗尽时，字幕生成落后于播放，UI 显示「网络较慢，字幕生成中」，
  不阻塞播放。

### 2. ASR 引擎：sherpa-onnx 为主，whisper.cpp 兜底

- 运行时用 **sherpa-onnx**（k2-fsa，Apache-2.0，C++ 核心 + ONNX Runtime，
  GitHub Releases 提供预转换模型包）：一个依赖同时覆盖 SenseVoice / Paraformer /
  Whisper / FireRedASR / Fun-ASR-Nano / Qwen3-ASR，并附带 Silero VAD、
  标点恢复、说话人分离，正好补上 M2 的周边需求。
- 默认模型 **SenseVoice-Small int8**（约 160MB）：中/英/日/韩/粤，非自回归，
  CPU 17× 实时，自带 ITN 与情感/事件标签；FunASR 实测中文 CER 7.81%
  （Whisper-large-v3 为 20.02%）。
- 可选模型（设置内切换、按需下载）：Paraformer-zh（自带标点 + 时间戳）、
  Fun-ASR-Nano / Qwen3-ASR（支持 hotwords 热词）、
  FireRedASR-AED（中文最强梯队，**许可证待确认**）。
- **whisper.cpp 兜底**：小语种场景；`initial_prompt` 注入「上一条 cue + 术语表」
  （约 224 token，自然语句包裹，不要只给词表）。
- 注意事项：
  - benchmark 不可横比（Whisper 在 aishell1 上 5.14%、在长音频实测上 20%），
    默认模型要用项目自己的片子测 CER 后最终确定；
  - SenseVoice 输出带 `<|zh|>` 富文本标签，需解析清洗；单段有时长上限，必须配 VAD；
  - sherpa-onnx 迭代快，集成时锁版本。

### 3. 同音词三层防御（输入法经验的复刻）

1. **热词注入**：Fun-ASR-Nano / Qwen3-ASR 的 hotwords 参数；whisper 侧用
   initial_prompt。内容 = 上一条 cue（保块间连贯）+ 片内术语表，每 90s 块重建。
2. **术语表后处理**：`data/glossary.json`，`错误片段 → 正确片段` 带锚点条件
   （原句包含某词才替换，防止「经济」被误改成「竟技」）。
3. **LLM 同音字纠错**（M3）：复用 llama-server，prompt 限定「只修明显同音错别字，
   不改写、不增删」，diff 比例过大则丢弃。
4. **产品闭环**：字幕上点错词 → 用户纠正 → 写入术语表 → 同时进入热词注入与
   后处理规则，越用越准。

### 4. 字幕渲染：自绘 overlay

- 挂在 `VideoWidget` 上的自绘 QWidget 图层，三模式（原文 / 译文 / 双语）切换、
  样式、进度提示完全可控，不依赖 libvlc 字幕引擎；延迟微调对接现有字幕菜单。
- cue 模型 `SubtitleCue`（start/end/原文/译文）+ `LiveSubtitleStore`：
  增量写 SRT、模式切换、订阅通知；外挂字幕（现有 `addSubtitleFile` 机制）继续可用。

### 5. 自动翻译（M3）

- llama-server 子进程管理（`ngl 99→40→20→0` 阶梯降级，ASR 占显存时先试 CPU）。
- 翻译调度：优先取播放头附近 8 条，拼 `序号|原文` 批量请求，正则解析 `序号|译文`
  回填，写 `.zh.preview.srt`。
- 翻译模型按需下载（HF + `hf-mirror.com` 国内镜像），默认 4B 级 Q4 量化，用户可换。

### 里程碑

| 阶段 | 内容 | 独立可用性 |
|---|---|---|
| M1 | 自绘 overlay + 三模式 + 延迟微调 | 可用现有外挂字幕验证渲染与交互 |
| M2 | 音频获取三模式 + VAD + ASR + 增量 SRT + 术语表/热词 | 自动识别字幕可用 |
| M3 | llama-server 翻译 + 同音字纠错 + 用户纠错闭环 | 双语字幕可用 |
